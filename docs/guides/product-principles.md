# DroneDream Agent 核心产品理念与真实闭环目标

## 文档定位

这份文档记录 DroneDream Agent 不应偏离的产品核心，也是后续架构设计、能力升级、仿真验收和真机准备工作的共同判断基准。

DroneDream Agent 的目标不是制作一个彼此割裂的演示，也不是让大模型只在任务开始前生成一段看起来合理的路线。产品必须在真实物理仿真中，把用户的高层自然语言意图转化为一项可以确认、可以执行、可以中途修改、可以安全结束并且有完整证据的长程无人机任务。

大模型必须是任务执行过程中的持续智能决策核心。它需要长期观察、理解、判断、规划和驱动任务，而不是偶尔调用一次。与此同时，飞控、碰撞检查、飞行包线和紧急处置必须继续由确定性系统提供不可绕过的安全边界。

普通路线点用于引导航迹，不是逐个悬停验收的关卡。原始路线和途中重规划都应由飞控持续跟踪、按弯道减速并纠偏，不在每个普通航点额外等待位置和速度连续稳定；取件、卸载、降落等实际动作按其物理需要执行稳定控制。后台感知和安全监测持续运行，不能把普通偏差或人为等待窗口到期直接变成任务失败。

挂载后的稳定判断关注实际悬停位置周围的漂移与速度，不重复要求返回挂载前的精确坐标；稳定测量与飞控必须使用一致坐标系。取件位置已由接近控制负责，载荷是否挂上由实际物理状态负责，不能把不同职责叠成互相冲突的等待条件。

## 一、产品要解决的真实问题

### 2026年10月12日再次确认的自然语言输入要求

用户的正常输入是模糊、口语化的高层意图，例如“帮我拿个东西”“帮我去信息科学楼拿个东西回来”。不要要求用户精确说出当前机型、地图、起点、飞行高度、悬停时间、航点、算法，以及完整的出发和返航步骤。Agent 应使用已有上下文和地图语义理解意图，调用工具形成完整计划；确实缺少取件地点、物品或接收人等必要信息时，用简短自然语言追问，不能编造事实或要求填写工程参数。

这是长期产品要求的重申。人工验收也必须从这种自然语言开始，不能用精确的起飞、悬停、降落脚本替代自然语言任务能力验收。三维路径由模型调用规划和验证工具生成，不能写死在某张地图上。跨聊天的界面、交付和验收要求统一记录在 `Q:\DroneDream-Workspace\DroneDream\docs\guides\PROJECT_MEMORY.md`。

传统无人机任务通常要求飞手始终跟随无人机，持续观察环境，并通过遥控器不断输入方向、高度、速度和姿态意图。即使用户只是想让无人机完成一次取件和送达，也需要投入大量注意力。

DroneDream 要把这种持续的人工操作转化为持续的智能代理操作：

- 用户只需要表达最高层级的任务意图；
- Agent 理解任务、提出完整计划，并让用户确认；
- 用户确认后，Agent 在任务全程持续参与；
- Agent 像飞手的大脑一样理解环境、选择动作、处理变化并保持最终目标；
- 飞控系统像人的肌肉和平衡能力一样，执行高频姿态稳定和电机控制；
- 独立安全系统像保护性本能一样，可以拒绝危险动作、悬停、降落或终止任务。

这不是“自然语言触发一条预设路线”，而是“自然语言委托一个能够持续操作无人机的智能飞行代理”。

## 二、代表性的长程任务

产品必须围绕真实用户会提出的完整任务设计，而不是只围绕几米距离的简单移动设计。一个代表性任务可能是：

> 从办公室起飞，穿过室内走廊，经楼梯区域下降，安全离开建筑，沿合适的室外路线前往指定取件点；到达后稳定悬停一段时间，等待工作人员挂载物品；确认负载变化后，把物品送到指定地点，随后安全返回办公室。

这个任务至少包含以下连续阶段：

1. 理解任务目标、地点、顺序、等待条件、返航要求和安全约束。
2. 深入理解所选地图、建筑连接关系、室内外过渡和可飞行空间。
3. 生成包含备选方案和失败处置的长程计划，交由用户确认。
4. 起飞后持续感知并执行，不把确认前的路线当成不可修改的脚本。
5. 在走廊、楼梯、大门、室外路径和目标区域之间持续进行局部判断。
6. 到达取件点后稳定悬停，可按任务要求等待十秒、二十秒或满足一个明确事件条件。
7. 识别物品挂载造成的重量、重心、动力和耗电变化，重新评估后续任务。
8. 根据实时环境、负载和电量完成送达。
9. 在条件允许时安全返航；条件不允许时进入明确的替代处置，而不是冒险继续。

任务的各阶段必须属于同一条连续状态链。已经发生的取件、装载、改令、等待和送达不能在重新规划时丢失。

## 三、大模型必须持续而深入地参与

大模型不是一次性规划器，也不是只在系统出错时才被调用的顾问。它应当在整个任务期间反复执行以下闭环：

> 感知当前世界 → 理解任务进度 → 评估风险与可行性 → 选择短期目标和动作意图 → 接收安全校验结果 → 观察动作结果 → 更新世界认知和计划

模型的持续参与应覆盖三个时间尺度：

### 全局任务尺度

模型理解用户最终要完成什么，维护取件、等待、装载、送达和返航等阶段之间的关系，并在任务改变时决定哪些阶段保留、修改、跳过或终止。

### 战术规划尺度

模型根据全局地图、局部环境、任务进度和风险，选择下一段路线、门或通道、飞行高度、等待位置、观察方向、避让策略以及是否需要重新规划。

### 短时操控尺度

模型像飞手操作手柄一样，持续提出受约束的短时控制意图，例如前进、侧移、升降、转向、减速、悬停、观察、后退或停止。每个意图只在有限时间和有限空间内有效，并必须经过确定性验证后才能执行。

模型不直接计算每个电机的毫秒级转速。高频姿态稳定、电机混控和紧急保护仍由 PX4、控制器和本地安全层执行。这种分工不会削弱模型的参与度：人类飞手同样不会逐个计算电机转速，而是持续观察、判断并操纵手柄。

模型的参与频率不能由固定的“每段调用一次”决定。系统应综合周期性更新和事件触发：环境变化、风险升高、路线受阻、传感器置信度下降、用户改令、负载变化和任务阶段切换都应触发新的模型判断。模型等待期间，无人机必须由确定性控制保持安全状态。

## 四、模型必须真正理解传感器和状态信息

模型不能只接收一堆未经解释的数字或图像。系统需要为每一种模块建立稳定、带单位、带时间、带坐标系、带置信度的结构化语义，使模型知道信息代表什么、覆盖哪个范围、是否新鲜以及应当如何使用。

| 信息来源 | 主要作用 | 模型需要理解的内容 |
| --- | --- | --- |
| 前向或多向视觉 | 识别人、门、标志、通道、障碍物和场景变化 | 画面时间、视角、可见区域、遮挡、不确定性和语义目标 |
| 深度相机、雷达或激光雷达 | 测量局部几何、净空、障碍距离和相对运动 | 坐标系、量程、盲区、噪声、动态目标及占据状态 |
| GPS 或其他全局定位 | 提供室外宏观位置和全局路线参考 | 精度、漂移、可用性、室内失效和地图坐标转换 |
| IMU、里程计和飞控遥测 | 提供姿态、速度、加速度、高度和飞行状态 | 当前运动趋势、稳定程度、跟踪误差、控制余量和数据时效 |
| 三维与语义地图 | 提供宏观环境、结构关系和已知约束 | 楼层、房间、走廊、楼梯、出入口、禁飞区、通行方向和目标语义 |
| 车辆模型 | 提供无人机尺寸、动力、传感器布局和飞行包线 | 净空需求、转弯半径、制动能力、续航和载荷限制 |
| 电池、电机和功率数据 | 评估续航、负载和动力异常 | 剩余任务预算、返航余量、电机不平衡和异常耗电 |
| 用户消息与任务记忆 | 维持任务目的、阶段和临时修改 | 哪些事实已经发生、哪些目标已改变、哪些授权仍然有效 |

局部信息与宏观信息必须同时存在。视觉和深度数据适合回答“眼前能不能通过”，全局地图和任务状态适合回答“为什么要通过这里、通过后去哪里”。任何一个层级都不能单独替代另一个层级。

## 五、环境重建与世界模型

Agent 需要拥有随飞行持续更新的世界模型，而不能只依赖起飞前的静态地图。世界模型至少应同时表达：

- 已知的全局地图和语义拓扑；
- 传感器观测到的局部可通行空间与占据空间；
- 人、车辆、门和其他动态对象的位置与运动趋势；
- 未知、被遮挡、过期或存在冲突的信息；
- 无人机自身位置、速度、朝向、尺寸和制动空间；
- 当前任务阶段、短期目标和可行备选路线。

环境重建的目的不是追求一份无限精细但无法实时使用的三维副本，而是为决策提供足够准确、能够增量更新、能够解释置信度的空间认知。系统应根据任务需要选择地图分辨率和更新范围：宏观层负责长程关系和路线预判，局部层负责实时避障和短程操控。

任何未知空间都不应自动当作安全空间。若传感器不足以确认通行，Agent 应主动观察、减速、悬停、换角度探测、选择另一条路线，或者请求人工处理。

## 六、深刻理解地图，并适应不同地图

School Map 是首个需要完整通过的真实物理仿真场景，但产品不能把任务逻辑、路线名称或环境假设写死在这张地图里。

在起飞前，系统可以给模型更充足的思考时间，让它建立对地图的整体认识：

- 地图有哪些楼层、区域、房间、走廊、楼梯、门和室内外连接点；
- 哪些区域允许飞行，哪些区域禁止进入；
- 哪些通道宽度、高度或转弯空间不适合当前无人机和当前负载；
- 起点、取件点、送达点、备降点和返航点之间有哪些可选路线；
- 哪些位置容易出现遮挡、定位漂移、弱信号、人流或动态障碍；
- 主路线失效时有哪些备选路线和安全等待点。

导入一张新地图时，系统应通过通用地图契约完成解析、语义标注、几何验证、坐标绑定、可通行性分析和资格检查。模型需要学习如何使用同一种结构化接口理解不同地图，而不是记住 School Map 的固定答案。

地图理解也不是一次性工作。飞行过程中，Agent 必须把现实观测与原地图对照，在门关闭、通道被占用、障碍新增或定位不一致时更新判断，并决定局部绕行、全局改道或安全等待。

## 七、用户中途改令必须保留任务连续性

用户可以在任务执行过程中继续使用自然语言修改任务。系统必须先稳定无人机，再理解改令对当前阶段的影响：

- 取件途中修改取件地点：保留已经完成的出发和航行状态，从当前实测位置规划到新的取件点。
- 已经取件后修改送达地点：保留已经装载的事实和新的载荷状态，只替换尚未完成的送达与返航计划。
- 悬停等待期间修改任务：先保持稳定，再判断继续等待、转移、取消还是降落。
- 返航途中新增任务：重新计算电量、负载、路线和安全余量；条件不足时不能盲目接受。
- 紧急停止或安全相关指令：不等待长时间模型推理，立即进入确定性的悬停、降落或其他安全程序。

任何替代计划都必须从当前可信位姿开始，不能回到旧起点重新播放，也不能让旧计划的副作用在新计划确认后继续发生。

## 八、负载变化是任务状态的一部分

在取件点悬停时，工作人员可能把物品挂载到无人机上。系统需要把这种变化视为真实的动力学状态转换，而不是简单等待结束后继续原路线。

可以综合以下信号判断是否发生装载以及装载是否稳定：

- 维持同一高度所需推力或油门的变化；
- 电机电流和功率变化；
- 垂直加速度与高度保持误差；
- 姿态偏差、电机输出不平衡和重心偏移迹象；
- 挂载前后短时稳定窗口中的统计差异；
- 用户、工作人员或外部装载确认信号。

确认负载变化后，应重新估计重量、重心、动力余量、制动距离、转弯能力、最大安全速度、下降速度、耗电速度和返航余量。必要时调整控制参数、降低速度、更换路线、缩短任务或拒绝继续。无法确认负载安全时，应保持悬停、请求处理或执行受控降落。

## 九、安全边界与模型权力

大模型应当深度参与，但它不能拥有绕过安全系统的权力。完整系统需要至少包含以下分层：

1. **任务与推理层**：理解用户意图、维护任务状态、规划和重新规划。
2. **世界模型层**：融合地图、视觉、深度、雷达、定位、遥测和历史信息。
3. **短时动作层**：把模型决定转换为带有效期、空间范围和约束的动作意图。
4. **确定性安全层**：检查碰撞、净空、速度、飞行包线、电量、身份、数据时效和授权。
5. **飞控执行层**：以高频闭环完成姿态稳定、轨迹跟踪、悬停和降落。
6. **证据与监督层**：记录输入、模型判断、批准结果、动作、传感器反馈和最终状态。

安全层可以否决模型，但不能悄悄替模型完成任务并让界面误以为模型持续参与。系统必须清楚记录：哪一步由模型决定、哪一步被确定性系统修正或拒绝、最终实际执行了什么。

当模型超时、结构化输出无效、视觉不可用、定位不可信、通信中断、控制数据陈旧或世界模型冲突时，系统必须 fail-closed：停止沿旧意图继续盲飞，进入有限时间的安全悬停、重新感知、重新规划、受控降落或人工接管流程。

## 十、真实性是不可妥协的验收原则

“真实”首先意味着在当前仿真阶段使用真实连接的系统链路，而不是互不相连的页面、脚本和动画：

- 使用真正的 PX4 SITL、Gazebo 物理、车辆模型和地图资产；
- 使用仿真实际产生的视觉、深度、雷达、定位和飞控遥测；
- 使用真实模型提供商调用和真实结构化响应，不用预写答案冒充模型判断；
- 模型输出必须真正影响后续可验证的任务决策；
- 动作必须真正改变仿真中的受控无人机；
- 用户确认、途中改令、负载变化和故障必须进入同一条任务状态链；
- 实际模型调用应形成真实的用量和审计记录；
- 成功必须由轨迹、净空、碰撞、传感器、飞控、落地、模型调用和状态证据共同证明；
- 失败、中断和未完成运行不能包装成成功。

真实性不等于目前已经具备真机通用能力。真实物理仿真通过后，还需要硬件在环、受控场地和真实无人机的分阶段验证。每个阶段都必须保留同样的证据和安全原则，不能把单张地图上的成功外推为任意环境已经可用。

## 十一、强化学习和其他增强方法的取舍

强化学习、模仿学习、轨迹优化、经验回放和长期记忆都可以研究，但它们是提升手段，不是产品目标本身。

只有在满足以下条件时才应引入某项增强方法：

- 能在明确的任务指标上带来可重复提升；
- 不破坏模型决策的可解释性、可审计性和任务连续性；
- 不绕过确定性安全层；
- 能在大量仿真场景中接受对抗测试和失败注入；
- 训练数据、奖励设计和适用边界能够被说明；
- 新方法失败时，系统仍能退回安全的基础策略。

强化学习更适合在隔离仿真中学习局部策略、恢复动作、速度选择或能耗优化，并通过确定性安全盾约束其输出。它不应未经验证就获得直接执行权。如果结构化世界模型、规划器和持续模型闭环已经能够可靠解决问题，就不必为了技术复杂度而强行加入强化学习。

## 十二、通用能力的验证矩阵

产品能力不能只靠一条成功录像证明。后续测试应逐步覆盖：

- 不同长度、不同楼层和不同室内外组合的长程任务；
- 不同地图、不同起点、不同目标和不同可通行结构；
- 墙体、树木、窄通道、环形结构、门和临时障碍；
- 静态障碍、移动障碍、人群和路线突然被占用；
- 视觉弱化、深度冻结、雷达异常、GPS 不可用、定位漂移和通信中断；
- 不同负载、偏心负载、装载失败和装载后动力不足；
- 取件前改令、装载后改令、返航改令、取消和紧急停止；
- 模型超时、模型输出无效、提供商切换和上下文过长；
- 电量不足、任务超时、无可行路线和必须安全降落的情况；
- 多次重复运行中的稳定性，而不是只保留最好的一次。

每个测试都应同时验证任务是否完成、模型是否真实持续参与、安全层是否真实工作、证据是否完整，以及失败时是否采用了正确的安全行为。

## 十三、后续升级时的决策原则

每一次能力升级都应回答以下问题：

1. 它是否让模型更准确地理解用户的完整任务？
2. 它是否让模型更持续、更及时地参与观察和决策？
3. 它是否改善模型对地图、局部环境、车辆或负载的认识？
4. 它是否提升长任务中的任务连续性和中途改令能力？
5. 它是否在真实物理仿真中产生了可测量的提升？
6. 它是否保留或增强了确定性安全边界？
7. 它是否适用于新地图和新任务，而不是只记住一个演示？
8. 它失败时，系统能否明确、安全、可解释地退出？
9. 它是否有完整的模型调用、传感器、动作和结果证据？
10. 它增加的复杂度是否确实值得？

如果一项修改只让界面看起来更智能，却没有进入真实执行闭环；只增加模型调用次数，却没有增加有效决策；只优化单次演示，却降低通用性或安全性，那么它不符合这份产品核心理念。

## 十四、最终成功定义

DroneDream Agent 的成功，不是无人机在一条预设轨迹上从一个点飞到另一个点，也不是大模型生成了一份漂亮计划。

真正的成功是：普通用户只表达高层自然语言意图，Agent 就能在陌生或变化的地图中建立正确认知，提出可确认的完整计划，并在较长时间内持续融合视觉、深度、雷达、定位、车辆和任务信息，像飞手一样不断观察和决策；当环境、负载或用户意图改变时，它能保留上下文、从当前真实状态重新规划，并在不可绕过的安全边界内完成取件、等待、装载、送达和返航。

这一过程必须在真实连接的仿真系统中完整发生、反复成功、能够失败得安全，并留下足以复核的端到端证据。只有达到这一标准，才能说我们做成了一个真正由自然语言驱动、由大模型持续参与控制的自主无人机 Agent。
