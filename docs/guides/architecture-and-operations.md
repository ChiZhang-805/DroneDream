# DroneDream 架构、资产与运行规范

更新日期：2026-10-22。

本文合并旧的存储说明、地图与资产交接、运行环境说明和已经稳定的架构结论。它说明当前应遵守的系统边界，不代表所有列出的能力都已完成验收。用户要求和界面细节的最新记录仍以 `DroneDream/docs/guides/PROJECT_MEMORY.md` 为准。

## 1. 系统目标与执行链

DroneDream 把用户的模糊自然语言任务转化为可确认、可执行、可中途调整并能形成证据的无人机任务。正常执行链为：

1. 从当前桌面版本的 Chatbot 接收自然语言。
2. 结合会话、当前地图、当前机型和账户状态理解目标。
3. 查询地图中的建筑、用途、入口、交接点和导航网络；缺少真正必要的信息时才自然追问。
4. 由模型生成任务阶段并调用规划工具；确定性规划器生成三维路径。
5. 对车辆包络、建筑占地、净空、定位、碰撞和执行权限做一次职责明确的校验。
6. 用户确认后，由 PX4、Gazebo、Runtime 服务和 Agent Core 执行；模型在规定的任务尺度持续参与。
7. 保存模型判断、路径、遥测、碰撞、载荷动作、完成状态和落地证据。

模型负责语义理解、任务状态、工具选择、阶段规划和重规划。高频姿态稳定、电机控制、硬碰撞边界和紧急处置由确定性组件负责。不得用一次关键词匹配或预写路线冒充模型参与，也不得为假设性异常堆叠重复关卡。

## 2. 代码与组件边界

| 区域 | 职责 |
| --- | --- |
| `Agent-Core` | 自然语言任务、地图语义、规划、安全仲裁、仿真执行适配和证据链。此目录本身就是正式核心仓库，开始工作前检查 Git 状态。 |
| `DroneDream` | 五个桌面版本共用的前端、桌面宿主、后端服务及项目记忆。 |
| `Build` | 构建输出、发布暂存、正式插件和模型包；不是源码事实源。 |
| `TestRuns` | 跨工作树验收证据和复验收据。每次真实运行使用新目录，禁止覆盖失败证据。 |
| `Q:\DroneDream-Workspace\Runtime` | 应用管理的 DroneDreamRuntime WSL/VHDX。不是源码树，只能通过产品的 Runtime installer/manager 修改。 |
| `Q:\DroneDream-Workspace\Caches\Runtime` | Runtime 可续传下载缓存，必须与 Runtime 导入目录分开。 |

五个桌面版本为 Universal、SIM、LAB、FIELD 和 AGENT。登录或注册成功后必须进入当前版本自己的 Chatbot。软件内使用邮箱和密码直接登录；浏览器网站可以继续提供浏览器登录。五版共存时，启动、更新和退出必须按实际安装目录及会话身份隔离，不能因可执行文件同名而结束其他版本。

五版必须从同一个仓库、同一个 `apps/desktop`、同一个前端和同一批共享服务构建，不建立五份复制源码。仓库一级目录固定为 `apps`、`services`、`platform`、`shared`、`release`、`tools`、`docs` 及必要的 `.github`；生成物只进入忽略的 `artifacts` 或工作区的 `Build`、`TestRuns`、`Caches`。版本差异只放在 edition manifest、品牌配置、安装标识、能力策略和隔离状态中。

## 3. 语言与本地化

- 首次启动统一使用英文，不按国家或系统区域自动切换。
- 用户可以在 Settings 主动切换中文，选择应持久化。
- 界面语言和对话语言是两条独立链路。界面、地图卡片和机型卡片跟随设置；AI 回复、澄清、计划和运行状态跟随本轮自然语言及会话最近明确语言。
- 中文任务使用中文地点、建筑和机型名称；英文任务使用英文名称，即使界面采用另一种语言。
- Kumpula Campus 的中文名为“赫尔辛基大学昆普拉校区”；Chemicum、Dynamicum、Exactum、Physicum 分别显示为化学楼、气象楼、信息科学楼、物理楼。

## 4. 地图导入契约

地图导入采用逐项弹窗，而不是点击 Import 后立即打开一个无上下文的文件选择器。导入契约管理以下四组内容：

| 组 | 内容 |
| --- | --- |
| Map scene | 可加载的场景或完整地图包，例如产品支持的 `.ddpkg`、`.zip`、`.sdf`、`.world`。 |
| Models & textures | 场景依赖的模型、材质、纹理和资源目录。 |
| Places & entrances | 建筑、设施、别名、用途、入口、出口、门号和交接点。 |
| Navigation network | 可通行网络、坐标绑定、限制区域和路线语义。 |

每项在前端只显示图标、短标题、已选文件和状态。等待为空圈，上传处理中旋转，文件收到后打勾；文件选择器按该项限制格式。上传成功只表示文件已经接收，不能和解析、资格检查或飞行成功混为一谈。取消选择保留上一份文件。AI 生成缺失材料必须由用户主动触发并明确消耗其额度。

完整地图包已经包含的依赖不重复索取。必要文件、数量、可省略项和组合关系留在导入契约中，不把工程说明段落塞进前端。

## 5. 地图预处理与地点语义

导入或升级地图时，应一次性建立可复用的地图索引：

- 逐栋识别建筑或设施，保留英文名、中文名、别名、真实地址、用途和部门。
- 记录全部有来源的入口、出口、门号、入口用途和室外交接位置；一栋多门不得压成一个点。
- 区分一栋建筑的分块、共享市政记录和真正独立的建筑。
- 建立物品、服务和地点之间带依据的候选关联，用于理解“去拿化学仪器”一类表达；关联只用于候选推断，不能伪造库存事实。
- 检查入口或交接点确实属于对应建筑，检查建筑到点的连线不会穿过自身或邻近建筑，并验证无人机三维可达性。
- 没有真实入口来源时，只能称为室外立面交接点，不得冒充已测绘门位。
- 后续导入新地图时，逐点、逐路段记录坐标、来源、置信度和其实际证明的事实；普通几何存在不能自动证明某条纹理是道路。路线端点必须与节点坐标吻合，全部任务点必须进入同一连通路网，并全图检查断路、重复边、自交、抖动、穿楼、穿树、越界和无任务意义的校外延伸。旧的本地解析流程继续作为离线、低预算底座；用户主动启动深度解析且给出预算后，可按疑点调用 OpenStreetMap 等可持久化数据和 Google Places、Routes、Roads 官方接口做在线复核。Google 结果只作有期限的建议，不能直接写成永久地图事实、绕过人工/独立证据或单独授予地图资格；凭据、网络、额度或服务失败时必须保留完整本地结果并正常降级。

当前正式内置地图只保留 Kumpula Campus。机场、竞技场、campus、诊所、酒店、office、triple-h 等旧 Open-RMF 演示资产不能因历史数据库残留或可生成预览而重新列为当前可用地图。用户上传的资产需保留，但“已收到”不等于“已具备当前自然语言任务能力”。

Kumpula 当前语义资产已为 41/41 条建筑记录建立通过几何与三维路线检查的室外交接点。该结论证明的是几何绑定完整，不等于所有入口均有真实测绘来源或每个点都完成逐点飞行。

## 6. 路径规划规则

- 新任务未明确出发地点时使用地图固定默认起飞点，由地图的运行起飞绑定唯一确定，不按别名排序。明确的建筑/地点出发指令优先，名称及别名解析后必须对应到该地点的可用起飞位置。未知或歧义地点不能静默替换为默认点。计划、仿真初始化和实际遥测需共同绑定选定起点；已有飞行中的改令保留真实当前位置。
- 全局路径不得把建筑屋顶当作捷径。建筑旋转后的二维占地按全高度禁穿区域处理。
- 路线优先沿建筑之间的道路、庭院和可飞空地绕行，不用起终点直线穿楼。
- 路径必须考虑无人机自身宽度、定位误差和控制余量。当前校园低空路线采用保守机体包络外至少约 0.8 米净空；实际阈值变更必须重新验证。
- 不贴墙飞行，不把刚好不碰撞当作合理路线。转弯使用碰撞复验后的圆滑曲线，避免难以跟踪的尖角。
- 二维任务视角显示的必须是实际执行的三维路线在地面的投影，并实时显示无人机位置。起点、终点及必要中转点按任务显示，路线使用密集短虚线。
- 普通航迹偏差允许在线调整和重规划；只要没有碰撞、损毁、失控或不可恢复故障，不因轻微偏离立即终止任务。

## 7. 飞行器资产

默认资产必须按真实任务需求筛选。预览可显示、SDF 可加载或与地图可配对，都不能替代真实任务验收。通过的保留，失败或不适合当前用途的从默认卡片、选择器和后台默认资源目录一起移除；用户上传资产和历史证据不得随默认目录清理而删除。

截至 2026-10-14：

- **X500 Depth**：已完成 Kumpula 校园取送往返和长距离路线物理仿真，是当前唯一默认机型。
- **X500 Flow**：实际导入/准备阶段发现单模型缺少飞行契约、完整依赖包入口存在歧义，未进入飞行验收，因此不作为默认机型。
- 其余旧默认机型：因不常用或没有当前验收依据，已从默认集合下架。

导入飞机时同样使用分项契约，明确机体模型、飞控配置、传感器资源、材质及运行依赖。资产进入默认集合前必须有真实导入、任务运行和结果证据。

## 8. Runtime 与状态管理

- Runtime、桌面软件、下载缓存和源码有不同职责；在工作区内使用独立子目录，Q 盘只保留一个 DroneDream 顶层入口。Windows 应用安装仍使用系统安装位置。
- Runtime Manager 负责安装、修复、更新、导入和所有权标记；手工移动 `ext4.vhdx` 会破坏产品状态。
- 一台机器只安装一个物理 `DroneDreamRuntime` WSL/VHDX。Universal、SIM、LAB、FIELD 和 AGENT 通过受约束的 Runtime profile、Engine Pack 和能力门选择所需模块，不各自复制一份 Runtime。
- 五版各自保留桌面安装目录、账号会话、WebView 数据、诊断目录和更新渠道；这些隔离状态不是五份 Runtime。任一版本卸载都不得删除共享 Runtime。
- 多个桌面版本同时运行时共享 Runtime，但各自维护桌面会话。普通启动可在既有 Runtime 操作期限内等待锁释放；真实错误不得无限重试。
- 关闭一个版本只释放该版本会话。仍有其他桌面会话时不得停止共享 Runtime；最后一个会话退出后才允许执行整体停止。
- 用户实验 jobs、trials、artifacts 与数据库记录属于一致性数据，只能通过产品删除 API、授权 receipt 或正式清理命令删除。

## 9. 存储职责

- `Q:\DroneDream-Workspace`：唯一开发者可写根目录，容纳源码、文档、构建、测试、缓存、归档和迁移收据。
- 正式源码只保留 `Q:\DroneDream-Workspace\DroneDream` 和 `Q:\DroneDream-Workspace\Agent-Core`。直接在这两个仓库更新；不再建立日期、审计、任务或版本命名的平行源码目录。旧目录统一收在 `Pending-User-Deletion`，不参与正常开发。
- DroneDream 构建输出：`Q:\DroneDream-Workspace\Build`。
- 发布暂存：`Q:\DroneDream-Workspace\Build\Release-Staging`。
- 跨工作树证据：`Q:\DroneDream-Workspace\TestRuns`。
- 可替换缓存：`Q:\DroneDream-Workspace\Caches` 或构建目录中的 `codex-cache`。
- `E:\D\DirMove\Downloads` 可用于模拟普通用户浏览器下载和双击安装，不作为源码或长期构建目录。
- Windows 用户安装和 LocalAppData 状态属于产品实例，不是开发源。
- 不得重建 `Q:\DroneDream-Builds`、`Q:\DroneDream-Releases`、`Q:\DroneDream-TestRuns` 等旧根目录，也不得用联接把一个项目伪装进另一个命名空间。

每次整理前检查相关 Git 状态。脏工作树、未推送提交、Runtime VHDX、Codex 会话、迁移证据、归档和用户实验数据均按保留状态处理。移动前记录源/目标、文件数和总字节，确认目标不存在，移动后复核同一清单。

## 10. 事实来源优先级

1. 当前 Git 工作树及其提交、diff 和仓库内契约。
2. 当前安装版的版本、哈希、运行状态和数据库事实。
3. `DroneDream/docs/guides/PROJECT_MEMORY.md` 中的用户要求和最新验收记录。
4. `TestRuns` 中对应运行的原始收据与不可变证据。
5. 本文与产品原则文档的长期规范。

历史交接、演示截图、PPT、旧源码清单和旧构建目录不能覆盖上述当前事实。
