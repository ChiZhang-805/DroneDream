# DroneDream 用户要求与项目记忆

更新日期：2026-10-13。本文记录用户已经明确提出的要求，供五个桌面版本、前端、Agent Core、验收和后续聊天共同使用。这里的要求不代表功能已经实现或验收通过。

## 自然语言任务入口

- 语言必须分成两条互不污染的链路：界面、地图卡片和无人机卡片跟随用户选择的系统/界面语言；AI 对话、澄清问题、错误回复和任务计划跟随用户本轮自然语言及该会话最近一次明确语言。中文任务必须显示中文地图名、机型名、地点名和步骤，英文任务同理，即使界面正在使用另一种语言。内置 Kumpula 地图的中文名统一为“赫尔辛基大学昆普拉校区”，四个具名建筑统一为化学楼、气象楼、信息科学楼、物理楼。

- 用户会说模糊、口语化、不完整的话，例如“帮我拿个东西”“帮我去信息科学楼拿个东西回来”。这是产品的正常输入，不是错误用法。
- 用户表达目的，Agent 负责理解任务、使用当前上下文和选中资产、查询地图语义、调用工具、补全执行计划。不能要求用户把机型、地图、起飞点、飞行高度、悬停秒数、航点、算法及返航步骤写成工程指令。
- 对取送任务，出发、交接、送达和正常返航等流程应由系统结合用户意图补全，并在可确认计划中清楚表达；用户不必每次重复“先起飞，再过去，再回来”。用户明确指定的单程、结束位置或改令优先。
- 真正缺少的信息，例如去哪里、拿什么、交给谁，不能凭空编造。先利用已有上下文，仍无法确定时用简短、自然的中文追问必要问题；已知地点可给简洁选项和自由输入。不要把内部字段、错误码或参数表交给用户填写。
- 地点应对应具体建筑和实际存在的落地或悬停交接点，不能所有任务都退化成唯一一个泛称“指定交付点”。需要多个有真实地图依据的可用地点。
- 用户通常对所选地图有一定了解，会直接说地点，或通过物品、用途、部门指代地点，例如“去物理楼拿个仪器”“取一下化学实验样品”。先使用地图中的名称、别名、用途、上下文和物品关联生成候选地点；不要忽略已有线索从头机械追问。用途关联是候选推断，不能据此声称物品实际存放在那里。
- 地图解析阶段应先整理建筑清单、名称与别名、用途与部门、带依据的物品/服务关联、建筑与入口/室外交接点的关系，供模型查询并缓存复用。地图变化时更新，不在每条消息上反复全图解析；不写死关键词到唯一目的地的规则。
- 地图准备必须逐栋覆盖，不能只标注少数知名建筑。每栋都要关联名称或真实地址、全部已知入口/出口及门号、入口用途、交接位置和来源；一栋多门要保留，建筑分块与独立建筑要分清。用户要求完整预处理；公开数据缺口必须继续列为未完成，不能编造门位或把自动生成的交接候选当成已核实入口。

## 大模型和执行方式

- 大模型必须真正参与判断、工具调用、路线规划和验证，不能只把一句话匹配到写死路线。
- 路径规划是三维的，需要考虑上下移动、几何净空、障碍和无人机能力。模型可以调用 A* 等合适算法及验证工具；换地图后仍应通过通用接口理解并规划。
- 模型持续参与任务全程，融合视觉、深度或雷达、定位、飞控遥测、地图、载荷和任务记忆。一次生成计划后播放固定动作，不等于自主 Agent。
- 取件、等待装载、送达、返回属于连续任务。中途改地点或改任务时，要保留已发生的事实，从当前真实状态重新规划。
- 模型与高频飞控分工，确定性安全边界继续生效。短暂模型延迟或非关键观测缺失不应无故卡死；涉及真实安全的缺失需要明确的悬停、重规划、返航或降落处置。
- 完整架构要求见工作区的 `Documents/DRONEDREAM_AGENT_CORE_PRODUCT_PRINCIPLES.md`；不要因前端改造丢失这些产品原则。

## 实现复杂度与性能

用户明确反对过度防御性编程。优先让正常路径简洁、直接、能运行；不要为了假设性异常堆叠重复校验、嵌套兜底、无谓等待或多轮模型复核。输入在负责它的边界校验一次，内部沿用明确契约；只有实际状态变化或明确故障需要时才重新检查或重试。缺少必要用户信息就直接自然追问，命名等非关键工作不能阻塞主任务。飞行安全、账户隔离和数据完整性的必要检查各有明确归属，避免重复设置同一关卡。

- 全图复核发现旧候选中 2 条门/楼到点的连线穿过其他建筑；Physicum、Exactum 原执行点虽可飞到，到各自入口的直线却穿过自身楼体。已离线重建逐栋交接绑定，41/41 条建筑记录具备几何与三维路线检查通过的室外交接点。附属建筑 29466、79952 的选点改为考虑相邻碰撞体并集后的完整外侧边界，解决单栋边界采样遗漏空地的问题；两点距所属楼约 2.7 米、3.2 米，不编造门位，不将其指向邻楼。
- Exactum、Physicum、校园图书馆虽共享市政建筑记录，使用各自设施几何/来源入口独立关联。没有来源入口的点只能称室外立面交接点；几何检查通过不等于真实入口测绘或逐点飞行通过。相同地址对应多栋楼时不得以列表顺序选定某栋。

- 2026-10-13：内置机型按当前常用任务需求筛选，并做真实导入和验收检查；通过的保留，失败或不适合当前用途的从默认卡片、选择器和后台资源目录一起移除。不能长期保留一批“待验证”的默认可选机型。用户自行导入的资产和历史证据不随默认目录清理而删除。
- 本轮筛选 X500 Depth 与 X500 Flow：Depth 通过校园取送往返物理仿真；Flow 实际导入/验收准备失败（单模型缺少飞行契约，完整依赖包入口歧义），未进行飞行。默认仅保留 Depth，其余 12 款下架。现行包回执为 `asset-qualification-57aa3819b5591401b2a92387`；新增既有几何所支持的室外交接节点后，内置资产旧版本引用按明确的版本替换清单迁移，不能任意替换用户上传资产的固定版本。这不代表任意自然语言任务均已验收。

- 用户可上传自己的地图。点击 Import 先打开逐项上传弹窗，不直接弹出文件选择器。每项只用图标、简短标题、文件名和状态；上传按钮用图标，等待为空圈，上传中旋转，收到文件后打勾。
- 支持哪些格式、每类数量、必要依赖和可省略项由导入契约管理，不在前端展示“必需/可选”、规则说明、帮助段落或工程要求。完整包已有的内容不要求重复上传。
- 上传成功就是文件已接收，不和解析、飞行验证混成同一个状态。后续处理失败不清空已收到的文件；取消文件选择保留上一份文件。
- AI 只能在用户主动点击后使用其额度；普通上传不调用付费模型。能生成的内容通过真实模型能力接入，不能用假生成动画或未实现按钮冒充。

- 使用真正可查看、可用于物理仿真的三维地图和无人机资产；不能拿平面图、宣传描述或动画冒充可执行三维场景。
- 地图资源应从正规来源深入检查实际内容、细节、适配性和许可；用户可以考虑付费资源。
- 产品目标包括细致的室内外环境和长程任务，但当前 Kumpula 资产是室外范围；不能宣称已有楼内、走廊或楼梯通行能力。
- 预览要能看清模型与实际参数。飞机和地图卡片在桌面宽度下一行三张，避免单列占左边、右边大面积空白；详情模型放大、信息紧凑完整。

## 界面与账户要求

- 产品首次启动一律使用英文，不根据国家、系统区域或安装器语言自动切换。用户只有在 Settings 中主动选择中文后，界面及该次自然语言任务的对话、计划和运行状态才使用中文；已保存的主动选择继续生效。
- 五个版本统一浅色；界面简洁，删除冗余说明性文字和无助于操作的状态展示，不把说明藏进默认展开的折叠区算作删除。
- 优先单屏、平整布局；合理使用模块高度和可用空间。需要滚动时保留滚轮或触控滚动能力，隐藏可见滚动条。按钮按任务关系重排，避免混乱和大块无意义留白。
- 用户点名移除的可见项包括 Rules & permissions、Model / Proposal only、Harness / Constraints enforced、Hardware / Denied、Hardware authority / Denied、Validated packs 0 of 8。移除展示不等于取消底层权限与安全控制。
- 启动页用正式无人机校园栅格插画铺底，背景延伸到顶栏，不用基础形状手工拼插画；左上品牌、右上设置，移除 Checked 和“让想法起飞”。
- 软件内直接邮箱密码登录，移除 Use Browser Sign-In 入口；浏览器网站自身仍可登录。
- 登录表单紧凑、字号及输入框适当放大，密码框下不留大空白；登录按钮及文字居中，下面提供可用的忘记密码入口。
- 注册页随字段增高，同屏显示邮箱、密码、确认密码和验证码；发送验证码是独立操作，最终按钮是“注册”或“完成注册”。
- 登录或注册成功进入当前软件自己的 Chatbot，不跨版本，也不默认进入 LAB 工作区。
- 启动标题短且保持一行；进度分步骤显示，当前步骤左侧有真实旋转动画，完成状态与实际进度一致。
- 启动卡片设计补充（2026-10-12，待实施）：移除卡片底部黄色的“Desktop sign-in could not be completed”说明块。卡片应恰好完整容纳 4 个步骤（流程需要时可为 5 个）及底部进度条、当前阶段和百分比，合理调整高度与间距，不留大块空白、不溢出、不出现底部内容被截一半的效果。用户本次明确要求先记录前端设计，暂不实施或发布；移除说明块不代表登录故障已经修复。
- 地图页体验补充（2026-10-12，待统一实施）：用户继续体验，本轮只记录、复述，待用户要求后与启动页一起统一修改。各上传项打开系统文件选择器时，应通过对应文件类型名称和扩展名筛选让用户知道该选什么格式；截图已显示地图类型筛选，实施时逐项核对，已有正确行为保留，缺失项补齐，不为此向弹窗添加说明段落。上传按钮的位置与对齐需要重排；用户否定当前摆放，未指定最终位置。
- 逐张核查地图卡片对应的实际资产、可用性和重复/废弃状态，移除确认无用或过时的卡片；不能仅因没有缩略图便认定资产无用，也不能把待处理的用户上传自动当作垃圾删除。保留的有效地图须从各自真实场景生成清晰截图作为缩略图，不长期使用通用图标占位，不拿其他地图的截图代替。
- 地图详情删除“Static preference, not flight permission; payload and live perception still require checks.”等说明性文字，以及 Height clipping、Volume centers 等预览工具控件。右侧专用于展示对应地图的真实 3D 示意，支持用户缩放、拖动平移和旋转查看；不把内部权限、验证文案堆进预览区。
- 每张地图详情左侧只保留必要、真实的信息，删减冗余描述、压缩排版并合理分配左右空间，使左侧信息和右侧 3D 预览完整放入弹窗。左侧不能靠隐藏滚动条保留长内容，不能要求滚动才能看到底部，不能截断；逐张卡片检查，不只修一张示例。

- 逐款核查无人机的实际资源、运行支持、传感器差异和任务适用范围，简明报告哪些已验证可用、哪些仍未验证或不支持。预览可显示、模型可加载、配对兼容不能替代真实任务可用性的证明；不能默认所有展示机型均已通过验收。
- Import map 与 Import aircraft 都必须明确导入契约：支持格式、各类文件数量、必要依赖及可省略内容；完整包不重复索取已有文件。按项提供合适的系统文件筛选和接收状态，前端维持简洁，不增加说明段落。
